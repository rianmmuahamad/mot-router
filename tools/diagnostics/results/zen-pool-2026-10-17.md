# Zen standby pool — 17 Oktober 2026 (WIB)

## Implementasi

Engine pool baru berada di router Go. Satu batch global, maksimal 10 probe yang
masing-masing dipin ke node native NodeBank, 10 IP unik per batch, target tiga
cadangan per model. Mengikuti maksimal tiga model dari trafik pengguna dalam
15 menit terakhir. Probe dan diagnostik gate tidak mengaktifkan aktivitas model.

Budget atomik 120 percobaan/jam disimpan dalam SQLite. Cache mengikat model,
endpoint, profil, identitas kredensial, node dan IP; TTL 15 menit. Tidak mengubah
selector MOT atau kuota pelanggan. Setelah stream pelanggan dimulai, tidak ada
replay. Rotasi otomatis hanya untuk koneksi rusak, bukan penolakan autentikasi,
region atau rate limit. Perubahan profil tidak menghapus cooldown penggunaan.

## Bukti lokal

- `go test -p 2 -buildvcs=false ./...`: lulus seluruh paket router.
- `go test -p 2 -buildvcs=false -race ./internal/server ./internal/store ./internal/zen`: lulus.
- Runtime: `GOTOOLCHAIN=go1.25.12 go test -p 2 -buildvcs=false -tags with_utls,with_grpc ./...`: lulus.
- JavaScript dashboard: `node --check`: lulus.
- Sepuluh probe TLS/CONNECT sungguhan berjalan serentak dengan sertifikat fixture
  dipercaya secara eksplisit. Header pin node benar; tidak ada PUT selector MOT.
- Fixture campuran cepat/lambat: hasil sehat pertama dipakai sebelum batch
  selesai; pekerja lain dibatalkan setelah tiga cadangan siap.
- Cold failover lengkap: tunnel pilihan awal gagal, probe node cadangan sukses,
  lalu prompt pelanggan dikirim sekali ke cadangan melalui tunnel terpisah.
- IP duplikat, TTL/profil berubah, konfigurasi invalid, budget habis, tunnel penuh,
  RAM rendah, rotasi manual dijeda, stream terpotong/salah/oversize, tool call,
  usage berulang, autentikasi, quota dan restart cooldown/budget diuji.
- 140 reservasi bersamaan menerima tepat 120; restart tetap menolak reservasi
  ke-121, dan jatah tersedia kembali setelah satu jam.
- Probe tidak menambah baris request atau pemakaian pelanggan.

Fixture seluruh tes pool: **2,15 detik**, user CPU 0,60 detik, system 0,34 detik,
peak RSS seluruh proses **21.760 KiB / 21,25 MiB** (termasuk harness, SQLite,
server TLS dan proxy lokal). Lihat `zen-pool-fixture-2026-10-17.txt`. Angka ini
mengukur fixture lokal, bukan klaim benchmark semua beban produksi.

## Validasi VPS

- Backup binary, konfigurasi/unit dan SQLite online dilakukan sebelum pemasangan.
  Kedua binary statis, tidak memerlukan glibc baru. Runtime tidak direstart ulang
  saat binary tidak berubah. Database live tidak dipulihkan/ditimpa.
- Pool pertama dimulai dijeda. Sampel produksi tahap paralel 1 menggunakan Muse
  melalui Playground menghasilkan `ZEN_OK`, usage asli **2.772 input + 45 output**.
- Probe cadangan pertama mendapat **HTTP 429**, 733 ms. Pool membatalkan batch
  setelah **satu** percobaan, tidak berpindah ke sembilan IP lain dan tidak
  menganggap node mati. Budget tetap **1/120** setelah pergantian binary.
- Upstream menetapkan Retry-After sampai **17 Oktober 2026 sekitar 07.00 WIB**.
  Cooldown dipertahankan. Uji inferensi produksi paralel 3 dan 10 tidak dilakukan
  karena limit tersebut; keduanya tersedia sebagai pilihan konfigurasi dan
  mekanisme 10 paralel sudah diuji melalui fixture TLS lokal.
- RSS gabungan router + runtime sebelum sampel 36.768 KiB; peak teramati 44.064
  KiB (**43,03 MiB**), bertambah **7,13 MiB** dalam sampel tahap 1. Ini bukan
  pengukuran peak produksi pada paralel 10.
- Aktivasi akhir produksi: **enabled=true, parallelism=1** sesuai tahap yang
  sedang divalidasi. Tahap lebih tinggi menunggu validasi setelah cooldown.
